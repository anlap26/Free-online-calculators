EXIF remover

Read device and GPS tags from a JPEG in the browser, then download a copy with those segments removed.

Passwords, photos, and text stay in this browser, except the IP test, which says which public service it calls.

A JPEG file starts with the bytes FF D8, then a series of segments. EXIF lives in an APP1 segment whose contents start with Exif. This page reads that segment in the browser and, when the tags are present, shows Make, Model, DateTime, Software, and GPS. It can then download a copy with APP1 segments and comment segments removed. The compressed image data stays. The pixels are not redrawn, so this path does not recompress the picture. The file never leaves the device. There is no upload, and the download is built from the bytes already in memory.

What the reader can miss

Uncommon tags may be missed. The reader is looking for those device and GPS fields, not for every metadata type on every format. A file that is neither a JPEG nor a PNG is not walked segment by segment. Other metadata can still be sitting in it. PNG text chunks can be dropped, and the page can show the text pairs it found before the drop. Re-encoding is the thorough option when you need tags this parser does not look for. Draw the picture through a canvas and save it again. That drops metadata, including kinds the segment reader skipped, and it also recompresses, so the file is no longer the original encoding. The image compressor is the page on this site that redraws through a canvas. Use the stripped download from this page when you want the same compressed image data with APP1 and comments gone. Use a re-encode when thoroughness matters more than a byte-for-byte image stream.

A place in the photo, and an address on the network

GPS in a photo is a location, a place the camera recorded. Hiding an IP is a different problem. Stripping the picture does not change the address a website sees when you load a page, and a VPN does not scrub a coordinate already baked into a file you later upload somewhere else. The IP test is the page for that address. It asks public services what they see, and it says so. NordVPN can change what that test sees, only while the tunnel is on. This page did not measure speed and does not rank NordVPN against any other tunnel. Plans change. The comparison guide says what to read on the current plan, which is the right place for that question.

Encrypting a note on the AES page does not touch the photo. An alias from the address builder does not either. If you are about to publish the picture, decide the two leaks separately: what the file still contains, and what address the upload request will show. Removing Make and Model also removes a convenient fingerprint of the camera, which matters on a shared album even when GPS was empty. DateTime can narrow when the photo was taken. Read the table before you download, so you know what was actually present rather than assuming every file carries a map pin.

Questions people ask

Is the photo uploaded?

No. The browser reads the file you picked. The download is built on the device. This site does not receive the bytes.

Which tags are shown?

For a JPEG: Make, Model, DateTime, Software, and GPS when those tags are present. Uncommon tags may be missed. The reader does not claim to parse every metadata type on every format.

What does the stripped JPEG still contain?

The compressed image data. APP1 segments, which is where EXIF lives, and comment segments are removed. The picture is not redrawn, so the pixels are not recompressed.

When should I re-encode instead?

When you want a thorough pass, including tags this parser skips. Drawing the image through a canvas drops metadata and also recompresses, so the file changes. The image compressor on this site is that path.

Does removing GPS hide my IP?

No. GPS is a place stored in the photo. The IP a website sees is a separate problem. Stripping the picture does not change that address. The IP test is the page for it.
