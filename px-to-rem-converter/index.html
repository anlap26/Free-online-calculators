PX to REM converter

rem is the pixels divided by the root font size. em uses the parent. vw is the pixels divided by the viewport width, times 100.

Prices and rates you type are yours. Vendor tariffs change. This page does not measure your live site.

Three conversions share the pixel length you type. rem is that length divided by the root font size. em is the same length divided by the parent font size. vw is the length divided by the viewport width, times 100, because one vw is one percent of the width. A zero or a negative root, parent, or viewport is rejected, since the page will not divide by zero or pretend a negative width is a screen. The three answers are independent. Changing the parent does not change the rem, and changing the root does not change the em.

A worked example

Take 32 pixels, a root of 16, a parent of 20, and a viewport of 1280. rem is 32 divided by 16, which is 2. em is 32 divided by 20, which is 1.6. vw is 32 divided by 1280, times 100, which is 2.5. If your root is not 16, the rem is not 2. Type the root the page actually uses, including a root you set in your own stylesheet. The form does not read that stylesheet. The 16 in the field is a common default, not a rule. Browsers often start at 16 pixels for the root font, and plenty of sites change it.

What scales, and what does not

rem follows the root. A person who enlarges the default font scales every length you expressed in rem, which is why body copy in rem can grow with that preference. px does not. A length in px stays the number of CSS pixels you wrote, even when the reader asked for larger type. That is the practical difference, not a moral one. Use px when you mean a fixed CSS pixel length, such as a hairline or a bitmap you already sized. Use rem when you mean type and the spaces that should travel with type.

em follows the parent, not the root. Nested em values compound. A child of 1.2 em inside a parent that is already 1.2 em is not 1.2 times the root. It is 1.2 times that parent. The converter shows one step, from the parent size you type to the pixel length. It does not walk a chain of elements. If you have three nested levels, multiply them yourself or type the parent size you already computed.

vw changes when the window changes. A font size in vw becomes smaller as the window becomes narrower, which is why a heading set only in vw can turn unreadably small on a phone. The converter will give you the vw for the width you typed. It will not stop you from using that number as a font size. If the width in the field is a desktop window, do not assume the same vw is comfortable at 360 pixels wide. Divide again with the narrow width if that is the case you care about.

None of these units fixes contrast. The contrast checker scores two colours and does not know the font size, even after you convert it. A large image is still bytes, which is the compressor. Hosting is a separate decision. Cloudways does not convert px to rem, and this page does not measure a host or recommend one.

Questions people ask

What is 32px at a root of 16, a parent of 20, and a viewport of 1280?

2 rem, 1.6 em, and 2.5 vw. Each figure uses only its own denominator.

Does rem follow the user font size?

rem follows the root. If the reader enlarges the default font, lengths in rem scale with it. Lengths in px do not.

Why can vw text become hard to read?

vw is a share of the window. When the window gets narrower, a font set only in vw gets smaller, sometimes unreadably so.

Is 16px required?

No. It is a common default for the root font. Type the root your page actually uses.

Does em compound?

Yes, in real CSS, because em is relative to the parent. This form shows one step from the parent size you type. It does not walk a nest of elements.
