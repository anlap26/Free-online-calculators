NordVPNSurfshark

Press the button and the browser does the lookups itself. It fetches api.ipify.org for the public IP, fetches ipwho.is for a coarse place and the network name, and opens WebRTC with stun.l.google.com. Candidate addresses from that connection are compared with the public IP. A different public address is reported as a leak. The place, when the lookup returns it, is a city, a region, and a country, not a street and not a house. The network line is the provider name from the same answer. If a lookup fails, that line stays empty. The page does not guess an address to fill the gap. The WebRTC listen is brief, a couple of seconds, then the candidates gathered so far are what you see.

Who sees the IP

Those services see the IP they are asked about. The requests leave your browser and go to them. This site does not receive the response. There is no account here that could store it. That is the exception named in the banner: passwords, photos, and text stay on the page, and this test is the one that says which public service it calls. Run it when you want to know the address a website would see, including after you have switched a tunnel on or off. Run it again after the change. One result from yesterday does not describe the path you are on now.

Names that end in .local are mDNS. The browser is hiding local addresses behind them. That is a privacy feature, not a leak, and the comparison skips those names. A web page cannot see your DNS resolver. This test does not ask which resolver you use, and an ordinary page is not able to see it. Do not read the result as a DNS leak test. The comparison that exists here is the public IP against the WebRTC list. A matching public address, with no extra public candidate, is the clean result this page knows how to report. It is not a certificate that every possible bypass is absent.

What a tunnel changes

A VPN tunnel changes the address those services see only while it is on. Disconnect, and they see the previous address again. The useful part of a leak test is noticing a WebRTC candidate that bypasses the tunnel and still names your real public address. NordVPN and Surfshark are two products that can hold such a tunnel. This page does not rank them by speed. It has no speed test, and it will not invent one. Plans change. Read the current terms on their sites. The comparison guide lists what to check instead of a ranking this site did not measure.

GPS inside a photo, which the EXIF remover reads, is a place you stood. It is not this network address. Stripping a picture does not change what ipify sees, and a tunnel does not scrub a coordinate already stored in a file. An alias from the address builder hides neither the IP nor the GPS point. A note on the AES page is a third job: secrecy of text, not of the path your packets take. The meeting planner only converts clocks across time zones. Questions people ask

Which services see my IP?

On the button press the browser asks api.ipify.org for the address, ipwho.is for a coarse place and the network name, and stun.l.google.com while it gathers WebRTC candidates. Those services see the IP. This site does not receive their response.

Will this show my DNS resolver?

No. A normal web page cannot see which resolver you use. This is not a DNS leak test. Compare the public IP with the WebRTC list.

What counts as a leak here?

A public address from WebRTC that differs from the ipify address. Names that end in .local are mDNS. The browser is hiding local addresses, which is a privacy feature, not a leak.

Does a VPN change the address this page shows?

Only while the tunnel is on. The lookups then see the VPN address. If WebRTC still offers your real public address, the page reports that difference. Turning the VPN off returns the previous address.

Which is faster, NordVPN or Surfshark?

This page did not measure speed and does not rank them that way. Plans change. The comparison guide lists what to check before you buy.
