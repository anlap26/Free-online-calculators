LLM token cost calculator

One call costs the input tokens times your input price plus the output tokens times your output price, both prices per million tokens.

Prices and rates you type are yours. Vendor tariffs change. This page does not measure your live site.

A token is a piece of text the model counts. It is not a whole word, and it is not one character. A short common word is often one token. A long word, a word in another script, or a string of punctuation can be several tokens. This page does not split a prompt for you. You type the counts a vendor tokenizer, or your API log, already produced. Input tokens are everything you send on that call: the system prompt, the instructions, notes you retrieved, and the question. Output tokens are the text the model writes back. Vendors price the two streams apart, so the form has two prices.

The cost of one call is the input tokens divided by one million, times the input price, plus the output tokens divided by one million, times the output price. A day is that cost times the calls you type. The month on this page is that day times 30. It is a flat 30, not a calendar month and not a vendor billing cycle. A platform fee, a tax, or a price quoted in another currency sits outside the formula. Type the prices you were offered, per million tokens.

A worked example

Take 1000 input tokens at 5 per million and 500 output tokens at 15 per million. The input part is 1000 divided by one million, times 5, which is 0.005. The output part is 500 divided by one million, times 15, which is 0.0075. One call is 0.0125. One thousand calls in a day is 12.50 for that day. Thirty days at the same pace is 375. Change any of the five numbers and the result moves with them. The page does not round this into a plan name.

The menu is a placeholder dated 2026-11-19

The model list is read from assets/js/llm-prices.js. The file says the figures were filled in on 2026-11-19, and the names say placeholder. The numbers are round so the form is not empty offline. They are not a quote from a lab. This page does not refresh them. Choosing a row fills the two price fields, and you can overwrite either field. The cost uses the fields, not the label in the menu. If a vendor changed a rate after that date, the file did not hear about it.

A long system prompt is paid on every call

The output price is easy to stare at. The input is where a long instruction hides. A system prompt of a few thousand tokens is sent again on every call, even when the person typed one sentence. Chat history, retrieved pages, and tool results sit on the input side too. Paste a whole article in so the model can rewrite it, and you pay for that article on every attempt, including the ones you discard. The output is only the reply. A short reply can still cost more than a long prompt when the output price is several times the input price. In the example, 500 output tokens cost 0.0075 and 1000 input tokens cost 0.005.

Nothing here is sent to a model. The script multiplies the form. It does not check that your tokenizer matches the vendor, and it does not apply a cache discount, a batch discount, or a free tier. If the invoice has a line the formula cannot see, the page will not invent it. Treat the total as a sketch of token spend, then read the bill you were actually sent.

Token spend is not the cost of being found

Paying a model to draft a paragraph is a different bill from being found for the query that paragraph should answer. The text checker can say how many words the draft has and how often a phrase appears. It cannot say which queries deserve that draft. Semrush is one place people look up queries, pages, and competitors. Opening it does not change the token arithmetic, and a research subscription is not the model invoice.

  • Count tokens with the vendor tokenizer, then type that count.
  • Put the system prompt in the input. There is no free field for it.
  • Include retries in the calls per day, not only the calls you keep.
  • Replace the placeholder prices before a total becomes a budget.

Questions people ask

What is the difference between input and output tokens?

Input tokens are what you send, including the system prompt. Output tokens are what the model writes back. They are priced separately, per million.

Does a long system prompt cost money on every call?

Yes, if the vendor counts it as input. It is sent again with each call, so a long instruction is paid every time, not once.

Are the prices in the model menu current?

No. They are placeholders in assets/js/llm-prices.js, dated 2026-11-19. Replace them with the prices on the vendor page you have open.

Does this page call a model?

No. It multiplies the token counts and prices you type. Your prompt is not uploaded.

Why is the month 30 times the day?

The page uses a flat 30 so the scale is obvious. It is not your vendor's billing cycle and not a calendar month.
