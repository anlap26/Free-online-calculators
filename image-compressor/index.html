Choose a file. The browser decodes it and draws it onto a canvas element, then asks the canvas for a blob in the format you picked: WebP, AVIF, JPEG, or PNG. The file is not uploaded. There is no account and no copy on a server of ours. When you download, the blob is the one the browser just encoded. Close the tab and that work is gone.

Resize keeps the aspect ratio and never upscales. The scale is the smaller of one, the max width divided by the current width, and the max height divided by the current height. A picture that already fits inside the box stays at its own pixel size. A picture that is wider or taller is reduced so both edges fit, and the other edge follows the ratio. The new width and height are rounded to whole pixels and never below one. You will see those dimensions next to the byte counts.

Quality and the formats

Quality is passed for the lossy formats. You type a number from the field, and the encoder receives it for WebP, AVIF, and JPEG. PNG is the lossless encoding of the resized pixels. A lower quality number asks the lossy encoder for a smaller file and a rougher picture. The page does not decide a correct quality for you. Look at the preview and the byte count, then keep or discard the result.

AVIF depends on the browser. If that browser cannot encode AVIF, the canvas returns no blob and the page says the encoding failed. Switch to WebP, JPEG, or PNG in that case. A failure is a limit of the browser you are using, not a measurement of your image and not a claim about another computer. WebP and JPEG are more widely encoded. PNG will often be larger than a lossy result of the same pixels, which is expected when you asked for a lossless file.

Bytes saved, and what they do not prove

Bytes saved are the original file size minus the new size. If the new file is larger, the difference is negative. That can happen when you re-encode a small PNG as a high-quality JPEG, or when the source was already compressed harder than the settings you chose. The number is arithmetic on the two sizes. It is not a score for the page that will contain the picture.

Re-encoding draws new pixels and writes a new file, so the metadata in the original is not carried along. That includes the camera notes and the location a JPEG often stores. The EXIF tool does that job more carefully for a JPEG: it can drop the metadata segments and leave the compressed image data in place, instead of painting the picture again. Use this compressor when you also want a new size or a new format. Use the EXIF tool when the pixels should stay and only the notes should go.

Questions people ask

Is the image uploaded?

No. The browser draws it on a canvas and encodes the blob locally. There is no account and no copy kept by this site.

Will a small image be enlarged to the max width?

No. The scale never goes above one, so a picture that already fits is not upscaled. Aspect ratio is kept.

What if AVIF fails?

The page says the encoding failed. AVIF depends on the browser. Choose WebP, JPEG, or PNG.

Does compression remove EXIF?

Re-encoding does not carry the original metadata along. The EXIF tool is the more careful way to drop JPEG metadata without painting the picture again.

Do the saved bytes speed up my live page?

Only if this image was the heavy part. The byte gap is original size minus new size. It does not measure the page.
