Put a key you must not lose in a manager

A hash cannot be turned back into the text, and a random key cannot be rebuilt from memory. Bitwarden is one place to keep that key. Plans change. A hash is not a password.

Bitwarden

This page makes four different things, and only one of them is a hash. UUID v4 values come from crypto.randomUUID. You can ask for several, up to twenty. They are random identifiers. They are not a fingerprint of the text in the box, and they are not a password. SHA-256 is the fingerprint. SHA-256 of the empty string is e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855. The box starts with a sample word, so clear it if you want to see that known value and confirm you are looking at SHA-256 rather than a vaguely similar digest. The same text always gives the same hash. That stable result is why a hash is not encryption. Encryption hides the text so that a reader without the key sees nothing useful. A hash lets you notice that the text changed. You cannot turn the hash back into the text. The page computes the digest locally. The text is not uploaded.

An unbiased number, and a key made of bytes

A random integer uses rejection sampling so the range is unbiased. The page draws a 32-bit value from crypto.getRandomValues and throws away draws that would make some integers between your minimum and your maximum more common than others, then maps what remains onto that range. A raw remainder would lean, because the size of the range rarely divides the 32-bit space evenly. The span you ask for has to fit in 32 bits. A random key is separate again: it is bytes from crypto.getRandomValues, shown as hex and as base64, at the length the form offers, 128, 256, or 512 bits. That key is a secret. Lose it and there is nothing to recompute, because it was not derived from a sentence you remember. The hash is not a secret in that sense. Anyone who has the text can produce the hash.

Do not store a hash as if it were the password

Do not call a hash a password, and do not save a hash in a manager as though it would log you in. Showing the hash to a login form will not open the account. If what you must not lose is the random key, put the key in a manager. Bitwarden is one place to keep it. Plans change, and this page does not quote a fee. The password generator is for passwords and passphrases, which are a different shape of secret, counted as length times log2 of an alphabet or as words times 8 bits on this site's list. Real secrecy for a note, the kind that hides the words, is the AES encryptor. A hash of that note would only prove the note is unchanged. It would publish nothing you can read, and it would also fail to conceal the note if you left the note beside it.

People sometimes hash a snippet while they are preparing a page: a small file, a block of JSON, a paragraph they do not want to alter by accident. The formatter and the text checker stay in the browser for that kind of editing. They do not replace the digest, and the digest does not edit the text. The password manager guide compares where a key you cannot rebuild should live. Use it for the key. Leave the hash as a fingerprint you can publish, recompute, and compare, which is the job it actually does.

Questions people ask

Can I reverse a SHA-256 hash?

No. SHA-256 is one way. The same text always produces the same hash, which is why it is not encryption. Encryption, which hides the text, is the AES page.

What should an empty field hash to?

SHA-256 of the empty string is e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855. The box starts with a sample word. Clear it if you want that known value.

Where do the UUIDs come from?

crypto.randomUUID, version 4. They are random identifiers, not hashes of your text, and not passwords. The form can make up to twenty at a time.

Why does the random number throw some draws away?

So the range is unbiased. A raw remainder would make some integers slightly more common. Rejection sampling keeps only draws that map evenly onto the minimum and maximum you set.

Should I save the hash in a password manager and use it to log in?

No. A hash is not a password. If you generated a random key, that key is the secret, and a manager is where it belongs, because you cannot rebuild it. Bitwarden is one place to keep it. Plans change.
